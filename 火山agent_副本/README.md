# 数字网格员

**AI Agent 驱动的社区治理自动化**

参赛队伍：玄黄二人组
参赛赛道：智慧政务 · 社区网格治理

本仓库是参赛作品的工程化交付物，包含一个可交互的「数字网格员」演示系统、21 篇可溯源的官方政策知识库，以及基于火山引擎 HiAgent 的配置与接入指南。

## 快速开始

项目已合并前端与轻量后端，默认零依赖（Node 内置模块）。

```bash
cd /Users/vincent/Documents/ChatGPT/火山agent
node server.js
```

浏览器打开 `http://127.0.0.1:3000`。本地模拟模式也可以直接双击 `index.html` 使用；真实接入 HiAgent 时请使用 `node server.js`。

## 功能模块

- 多模态诉求接入：微信群、小程序、电话三种渠道，支持语音转写模拟
- 意图识别与上下文补全：自动分类诉求类别，关联居民历史记录
- 知识库检索（RAG）：基于福州及鼓楼区政策法规的向量检索与引用溯源
- 自动派单与工单生成：按责任部门自动生成标准化工单并推送
- 主动回复与闭环归档：Agent 直接回复居民处理进度，网格员一键确认归档
- 数据看板：受理量、响应时间、自动闭环率、政策问答准确率等指标

## 与 HiAgent 平台配置一致

本地演示系统的节点与 HiAgent 个人空间中的「数字网格员」保持一致：

- 工作流「意图识别」：分类为政策咨询类、环境卫生类、噪音扰民类、违建秩序类、其他诉求
- 子智能体：意图分类助手、政策解答专家、工单处理agent
- 知识库：「鼓楼区政务咨询库」（本地 21 篇官方政策，含网格管理、12345、市容环卫、物业服务、违建、养老、消防、养犬、惠企等分类）
- 派单链路：工单处理agent → 代码聚合 → HTTP 节点派发责任部门
- 人机协同：Agent 自动执行，网格员确认归档

## 合体：接入 HiAgent 真实接口

本地演示默认运行在模拟模式；切到「系统配置 → HiAgent 真实接口」后，页面会把诉求提交给 HiAgent 发布后的 API，并把真实回答展示在演示界面中。操作步骤见 [docs/合体指南.md](docs/合体指南.md)。

后端 `server.js` 负责静态托管与 HiAgent 代理转发，避免浏览器跨域，并避免把 API Key 暴露在前端。

## 目录结构

```text
.
├── index.html                    演示系统入口
├── styles.css                    演示系统样式
├── app.js                        演示系统交互与模拟 Agent 流水线
├── hiagent-client.js             HiAgent 接口适配层（可切换模拟/真实模式）
├── server.js                     本地后端：静态服务 + HiAgent 代理
├── package.json                  启动脚本
├── data/
│   ├── knowledge-base.js         官方政策知识库（前端使用）
│   ├── policy_kb.json            官方政策知识库（HiAgent 字段映射用）
│   └── hiagent-import/           21 篇 Markdown，可直接上传 HiAgent
└── docs/
    ├── 方案说明书.md              参赛作品技术方案
    ├── HiAgent配置指南.md         火山引擎 HiAgent 落地配置
    └── 演示脚本.md                现场演示脚本与用例
```

知识库变更后，可运行 `node tools/export-hiagent-kb.mjs` 重新生成 `data/hiagent-import/官方政策/` 下的 Markdown 导入包。

## 重要说明

- 演示系统运行在本地模拟模式，不访问真实 HiAgent 服务；系统配置页预留了平台地址、应用 ID、模型与 API Key 接入位。
- `policy_kb.json` 与 `knowledge-base.js` 中的政策文件均来自福州市、福建省及鼓楼区公开政府渠道，每条记录保留标题、文号、发布日期和官方原文链接；导入前仍建议对照官网原文做一次时效性校对。
- 项目遵循「Agent 自动执行 → 人类最终确认」的人机协同范式，工单归档必须由网格员确认。
